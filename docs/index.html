DModE · Tutorial

Differential RNA Modification and Expression Analysis

A reproducible, command-by-command walkthrough of every DModE workflow, applied to a long-read direct-RNA sequencing dataset comparing HEK293 cells against Universal Human Reference RNA (UHRR). The dataset is downloaded in step 2.

Overview

DModE is a Python package and command-line tool for the integrated analysis of RNA base modifications (m⁶A, m⁵C, Ψ, 2′-O-methylations, …) and gene/transcript expression from long-read sequencing data. This tutorial applies every DModE workflow to a publicly available example dataset, which is downloaded in step 2, so that each command can be reproduced exactly as shown.

The example experiment is a two-condition comparison:

  • HEK — HEK293 cell line (biological samples HEK_A, HEK_B)
  • UHRR — Universal Human Reference RNA (samples UHRR_1, UHRR_2, UHRR_3), used as the reference condition

Libraries were prepared with the Oxford Nanopore direct-RNA chemistry (RNA004) and aligned and quantified against GENCODE release 49 (human, GRCh38).

Requirements

A Linux or macOS shell, Python ≥ 3.10, pip, wget, and an internet connection to retrieve the example data (step 2) and the genome annotation (step 3). The differential-modification and integrated workflows are memory-intensive; a few GB of free RAM is recommended.

1Installation

Create an isolated environment (recommended) and install DModE from PyPI:

# create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate
# install DModE and its dependencies
pip install dmode

This puts the dmode command on your PATH. Verify it:

dmode --help

To install the latest development version from source instead:

git clone https://github.com/stegiopast/dmode.git
cd dmode
pip install -e .
Tip

DModE pulls in scientific dependencies (pydeseq2, scikit-learn, umap-learn, pyranges, …). Installing inside a fresh virtual environment or conda environment avoids version clashes with other projects.

2Download the example data

The complete example dataset — Modkit BED files, featureCounts matrices, Salmon quantifications, and the four ready-made metadata sheets — is archived on Zenodo. Download the archive and unpack it:

wget https://zenodo.org/records/20496900/files/dmode_tutorial_data.tar.gz
tar -xzf dmode_tutorial_data.tar.gz
cd dmode_tutorial

After unpacking, the directory contains the per-sample data folders and four metadata sheets:

dmode_tutorial/
├── genome/            # genome-aligned Modkit BED files
├── transcriptome/     # transcriptome-aligned Modkit BED files
├── featurecounts/     # featureCounts gene-count matrices
├── salmon_output/     # Salmon transcript quantifications
├── genome.tsv  transcriptome.tsv  featurecounts.tsv  salmon.tsv
└── complete.sh        # wrapper that runs every workflow (step 5)

DModE accepts its inputs either as a tab-separated metadata sheet (File, Condition, and — for expression — Sample columns) or as explicit file lists. This tutorial uses the four metadata sheets. Each describes the same five samples for one data modality:

Metadata sheetData modalityUnderlying files
genome.tsvGene-level modificationsModkit BED files in genome/ (aligned to the genome)
transcriptome.tsvTranscript-level modificationsModkit BED files in transcriptome/ (aligned to the transcriptome)
featurecounts.tsvGene-level expressionfeatureCounts matrices in featurecounts/
salmon.tsvTranscript-level expressionSalmon quant.sf files in salmon_output/

For example, genome.tsv looks like this:

File                         Condition   Sample
genome/HEK_A_genome.bed      HEK         HEK_A
genome/HEK_B_genome.bed      HEK         HEK_B
genome/UHRR_1_genome.bed     UHRR        UHRR_1
genome/UHRR_2_genome.bed     UHRR        UHRR_2
genome/UHRR_3_genome.bed     UHRR        UHRR_3

The file paths inside each sheet are relative, so all commands must be run from within the dmode_tutorial/ directory you just entered.

Note on runtime and resources

These are genuine long-read datasets: the transcriptome BED files reach ~200 MB and the featureCounts matrices ~65 MB each. The differential-modification and integrated workflows take several minutes and a few GB of RAM. Run the basic-statistics commands first to confirm the setup before launching the more demanding steps.

3Download the annotation (GTF)

Every DModE workflow requires the GTF annotation of the genome the data was aligned to. This dataset was aligned and quantified against GENCODE release 49 (human, GRCh38); this can be confirmed in the header of any featureCounts table, which names gencode.v49.basic.annotation.gtf.gz. Download it from GENCODE into the current directory and decompress it:

# GENCODE v49 basic annotation (matches the example data)
wget https://ftp.ebi.ac.uk/pub/databases/gencode/Gencode_human/release_49/gencode.v49.basic.annotation.gtf.gz
# decompress — DModE reads the plain-text .gtf
gunzip gencode.v49.basic.annotation.gtf.gz
Mirrors and alternatives

Any GENCODE or Ensembl GRCh38 annotation whose gene and transcript IDs match the data is suitable; the basic annotation is the closest match. The comprehensive annotation (gencode.v49.annotation.gtf.gz) is larger but also works.

Finally, define a few shell variables so the commands below stay short, and create the output folder — it must exist before the first command is run:

GTF=gencode.v49.basic.annotation.gtf
OUT=results
REF=UHRR        # reference (control) condition
mkdir -p $OUT

4Running the analyses

Each command below is self-contained and writes its results into $OUT. The commands correspond exactly to those in the bundled complete.sh script (step 5) and use the four metadata sheets from the example dataset.

4.1 · Exploratory statistics — gene level

Exploratory quality control should precede any differential testing. gene_basic_statistics produces PCA and UMAP projections for assessing sample clustering, bar and violin plots of modification-site counts and frequencies, and sample-to-sample correlation matrices.

dmode gene_basic_statistics -m genome.tsv -g $GTF -o $OUT
Expected outputs

Written under results/gene_basic_statistics/:

  • *_PCA_plot.png, *_UMAP_plot.png — sample clustering
  • *_modsite_barplot.png — modification sites per sample
  • *_modification_distribution.png, *_violin_plot.png — frequency distributions
  • *_sample_to_sample_correlation.png — pairwise correlation
Restrict to one modification

By default DModE analyses every modification type it detects. Add --modification m6A (or any of m6A Am Ino pseU Um Gm Cm m5C) to focus on specific marks, and --coverage_filter / --frequency_filter to tune site inclusion.

4.2 · Exploratory statistics — transcript level

The same QC, computed on the transcriptome-aligned Modkit BED files.

dmode transcript_basic_statistics -m transcriptome.tsv -g $GTF -o $OUT

4.3 · Metagene profile

metagene_plot maps modification frequencies along a normalised gene body (5′UTR → CDS → 3′UTR) so you can see where modifications accumulate.

dmode metagene_plot -m genome.tsv -g $GTF -o $OUT
Single gene

Add --gene_id ENSG00000XXXXXX (the -x flag) to produce a metagene profile for one gene of interest instead of the transcriptome-wide average.

4.4 · Differential modification — gene level

diff_gene_modification tests every modification site for a significant change in modification frequency between conditions, using a logistic-regression test with SLIM (default) or Benjamini–Hochberg multiple-testing correction. UHRR is the reference level, so the comparison reported is HEK vs UHRR.

dmode diff_gene_modification -m genome.tsv -g $GTF -o $OUT -r $REF
Expected outputs

Under results/diff_gene_modification/HEK_VS_UHRR/:

  • Volcano plots — combined and per chromosome
  • *_diff_gene_mod.tsv — all tested sites with statistics, fold change, adjusted p-value
  • *_diff_gene_mod_genes.tsv — significant sites annotated with gene names from the GTF

Useful extras: --alpha 0.05 (significance threshold), --chromosome chr1 (restrict to one chromosome), --p_value_correction BH.

4.5 · Differential modification — transcript level

Identical logic, on the transcriptome-aligned data.

dmode diff_transcript_modification -m transcriptome.tsv -g $GTF -o $OUT -r $REF

4.6 · Differential gene expression

diff_gene_expression runs a pydeseq2 (DESeq2-style) analysis on the featureCounts matrices, generating volcano/MA plots, heatmaps and correlation matrices.

dmode diff_gene_expression -m featurecounts.tsv -g $GTF -o $OUT -r $REF
Expected outputs
  • Volcano & MA plots, pairwise and global expression heatmaps
  • Sample–sample correlation matrix
  • *_genome_diff_expression_results.tsv — full DESeq2 result table

4.7 · Differential transcript expression

The same DE workflow on the Salmon quant.sf quantifications.

dmode diff_transcript_expression -m salmon.tsv -g $GTF -o $OUT -r $REF

4.8 · Integrated expression + modification — gene level

The most comprehensive workflow. It runs differential expression and differential modification together, then produces correlation plots that relate expression fold-changes to modification-frequency changes on a per-gene basis. It requires two metadata sheets: counts via -m and Modkit BED files via -n.

dmode diff_gene_expression_and_modification \
    -m featurecounts.tsv \
    -n genome.tsv \
    -g $GTF -o $OUT -r $REF
Extra outputs beyond the individual analyses
  • Expression vs. modification-difference scatter ("eruption" plot)
  • Expression–modification correlation scatter
  • Bar plot of the top-50 genes carrying the most significant differential modification sites

Separate thresholds here: --alpha_expression (-A) and --alpha_modification (-a).

4.9 · Integrated expression + modification — transcript level

The transcript-level equivalent: Salmon counts via -m, transcriptome Modkit BEDs via -n.

dmode diff_transcript_expression_and_modification \
    -m salmon.tsv \
    -n transcriptome.tsv \
    -g $GTF -o $OUT -r $REF

5Run the whole pipeline at once

The example dataset ships a complete.sh wrapper that runs all nine workflows in sequence. With the data and annotation in place (steps 2–3), a single call reproduces everything in this tutorial:

mkdir -p results
bash complete.sh \
    -g gencode.v49.basic.annotation.gtf \
    -r UHRR \
    -o results \
    -G genome.tsv \
    -T transcriptome.tsv \
    -F featurecounts.tsv \
    -S salmon.tsv

6The HTML report

After each command finishes, DModE scans the output folder and (re)builds a single self-contained dmode_report.html inside results/. It groups every figure by analysis type, modification, and condition comparison into a navigable, click-to-zoom interface — open it in any browser:

xdg-open results/dmode_report.html   # Linux
open results/dmode_report.html       # macOS

You can also regenerate the report manually from Python at any time:

from dmode.report.generate_report import generate_html_report
generate_html_report("results")
Preview

The example dataset includes a pre-built dmode_report.html from a complete run, so the finished product can be inspected before running any of the workflows.
